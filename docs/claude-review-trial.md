# Claudeレビューの30％目標を測る

[標準方針](claude-review-policy.md)に基づく計測手順です。
2026-11-02のユーザー指示に基づく試行です。
１回の依頼について、Proの５時間枠を約30ポイント使う範囲を目指します。
親と専門担当を含みます。残り枠の30％や、各担当30％ではありません。
目標以下で品質を満たせれば、余った枠を使い切る必要はありません。

## 実行前

1. 使用率、確認時刻、リセット予定時刻をアカウント画面で記録します。
2. 対象base/head、未コミット差分、適用設定の版を固定します。
3. チケット本文と確定した受入条件を担当に渡します。
4. 初回発見を測る場合、過去の所見・正解・採点表は担当に渡しません。
5. 通常の `adv:` を新しいClaude Codeセッションで実行します。
   必須のReact/Nest相談は、ADV自身が担当範囲を限定して依頼します。

既存設定へのリンクや配置は、実際のプロジェクトで確認します。
この文書を作っただけでは、インストール済み定義の更新を証明できません。
別のモデルや権限への変更は、今回の試行に含みません。
独立したCR/QA/E2Eは、依頼された場合にそれぞれ測ります。

## 使用率の記録

| 項目 | 記録値 |
|---|---|
| 対象・設定版 | |
| 開始時刻／終了時刻 | |
| 開始時の使用率／終了時の使用率 | |
| 開始時／終了時のリセット予定 | |
| 同じ枠での他チャットの使用 | なし／あり／不明 |
| 使用率差 | 終了％ − 開始％（ポイント） |
| 集計状態 | MEASURED / CONFOUNDED / INCOMPARABLE / NOT_MEASURED |
| 親・各担当のtokensと計数定義 | |
| 親子使用量の重複有無 | |
| 入力／キャッシュ入力／出力 | |
| 各担当の時間・呼出し数・切断回数 | |

同じリセット枠で、他の作業による使用がないときに比較できます。
他のチャットが動いた場合はCONFOUNDEDです。
途中で枠が切り替わった場合はINCOMPARABLEです。
表示値を取得できない場合はNOT_MEASUREDです。
丸められた表示値による差には、その丸めの幅が含まれます。
tokensや料金から、Pro使用率を換算しません。
親子の重複が不明なtokensは参考値として分けて記録します。

約30ポイントに近づいた場合、進行中の限定した確認をまとめます。
残る必須確認は、担当・根拠・次の確認範囲を残します。
未完了をCOMPLETEやAPPROVEに変えません。
続行する場合は同じ担当へ戻し、追加使用量も累積して記録します。
使用率が不明な場合も必要な確認を進め、予算達成は未確認とします。

## 品質の評価

結果確定後に、評価担当が過去の記録や正解と照合します。
この採点用記録を初回レビュー担当の入力へ戻しません。

- 実際に到達する不具合を拾ったか。
- 正常な例外や意図した動作を、誤って不具合にしていないか。
- 規約違反は該当条項と例外を確認したか。
- エラーの発生元から境界まで追い、別の取得経路も確認したか。
- 不明な受入条件、未読の必須節、未実行の検証を残したか。
- 既存問題と今回の劣化を分け、判定への影響を説明したか。
- mockで外した子要素の動作を、確認済みとしていないか。

指摘数、読み取った量、短時間、低使用率だけでは合格にしません。
同じスナップショットと入力で比較し、別タスクでも繰り返します。
初回は採点対象の所見を伏せます。修正確認では全open項目を引き継ぎます。

## Claudeへの依頼例

```text
adv: 指定した差分を初回レビューしてください。
対象: <リポジトリ絶対パス、base/head、未コミット範囲>
要件: <チケット本文と確定回答のファイル>
除外: <環境ファイル、別worktreeなど>
設定: <有効な共有設定の版・参照元>
現在の使用率: <表示値、不明ならNOT_MEASURED>
開始時刻・リセット予定: <値>
親と必須相談を含め、Pro５時間枠で約30ポイントを目標とします。
不足する必須確認は未完了として残してください。
コード読取と実行結果を区別し、実行・修正は依頼に含めません。
過去のレビュー結果や比較報告は、この初回調査に使わないでください。
```

この試行は独自のadv担当を使います。
公式のPR用Code Reviewサービスや/code-reviewへの切替ではありません。
