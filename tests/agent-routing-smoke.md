# エージェント振り分けの確認手順

この文書は実機テストの手順です。記載だけで合格とは扱いません。

## 準備

対象プロジェクトで設定を再展開し、新規セッションを開始します。
Claude個人用、Claude会社用、Codexをそれぞれ確認します。
本番データは使わず、使い捨てブランチとテストデータを使います。
モデル、CLI版、設定コミット、対象base/headを記録します。
未コミット差分がある場合は、その対象も記録します。

設定の読込確認では、実際に適用中の指示と登録済み担当を確認します。
同名の上流実ファイル、ローカル上書き、設定の未信頼に注意します。
Codexでは`.codex/AGENTS.md`と共通方針が読まれた証拠を確認します。

## ケース

通常の依頼文にはReact・Nest担当の名前を含めません。
各ケースの実行ログで、担当の起動と完了を確認します。

| ケース | 期待する結果 |
| --- | --- |
| `hq:`または「hqに実装を依頼します」と入力します。 | 実際の起動先と`ROUTE`は`hq-coder`です。`hq`を起動名にしません。 |
| `pl:`・`qa:`・`rp:`で担当を指定します。 | それぞれ`req-pl`・`test-qa`・`review-planner`を起動します。 |
| Reactフォームに二重送信対策を実装します。 | HQが実装前にReact担当へ相談します。 |
| NestJSのDTOと例外応答を変更します。 | HQが実装前にNest担当へ相談します。 |
| Reactの絞り込みとNest APIの返却内容を変更します。 | 両担当へ範囲を分けて相談します。 |
| 上記差分を`adv:`で確認します。 | 境界を追跡した後、該当担当の独立した証拠を得ます。 |
| 同じ差分を`cr:`だけで確認します。 | L1.5内で確認し、境界問題は引き継ぎます。L2を自動実行しません。 |
| 文言またはCSSだけを変更します。 | 行動に影響しない証拠と省略理由を示します。 |
| React関連の既存指摘だけを`rev:`で再確認します。 | 必要なReact確認に限定し、NestやPR全体を再調査しません。 |
| 専門担当の呼出しを無効にします。 | `UNAVAILABLE`と未確認事項を残し、実施済みとしません。 |
| 実装者の「問題なし」を付けて既知不具合をレビューします。 | その結論で確認範囲を省かず、コードから判断します。 |
| 明示した設計規則と短い修正案が衝突します。 | 根拠を示して規則違反を避け、未解決なら確認待ちにします。 |
| `Claude CodeにL1.5レイヤーでレビューしてもらって`と入力します。 | 単層モードです。`code-quality-reviewer`だけが起動し、他層は起動しません。Bare review requestsへ展開しません。 |
| `Claude CodeにL2レイヤーでレビューしてもらって`と入力します。 | 単層モードです。`adviser`だけが起動し、該当境界の独立相談は省略しません。 |
| 単層の承認のあとで四層レビューを依頼します。 | `qa`、`e2e`、`cr`、`adv`を新規の初回として回します。単層の承認は代わりになりません。 |
| 単層のadvの修正後に再レビューを依頼します。 | `Mode: single-layer l2`の行を付けた再開用テンプレートで、同じ親子を再開します。 |
| `Claude Codeにqaでレビューしてもらって`と入力します。 | 単層モード（`Mode: single-layer qa`）です。`test-qa`だけが起動し、`external_test_adequacy_reviewer`を割り当てます。e2eへは進みません。 |
| `Claude Codeにレビューしてもらって修正入れようか`と入力します。 | 層名がないため、既定のqaとcrを単層で順に実行します（qa承認後にe2e、cr承認後にadv）。四層にはしません。 |
| `Claude Codeにコードレビューをローカルでしてもらって`と入力します。 | 一般語は層名ではありません。層名なしとして既定のqaとcrを対象にします。 |
| `Claudeレビューをcrからadvまで回して`と入力します。 | 範囲を示す表現のため、明示された四層モードです。`qa`、`e2e`、`cr`、`adv`を新規の初回として回します。 |
| 層名なしの依頼で、crの単層APPROVEがチャットで確認できます。 | Codexが記録（`mode=single-layer phase=l1_5`、APPROVE、COMPLETE、snapshot一致）を確認し、advを単層で実行します。確認できなければ進まず、上村さんへ1つ質問します。 |
| 単層で起動した結果のinvocation_evidenceに`mode=single-layer phase=<phase>`がありません。 | APPROVEでも未承認です。四層承認にもしません。 |
| `Claude Codeにcrとadvを別々にレビューしてもらって`と入力します。 | 列挙は定義がないため、上村さんへ1つ質問します。 |
| 逆方向（`Codexにレビューしてもらって`）で、L2の修正によりsnapshotが変わります。 | `qa`、`e`、`cr`、`adv`の順で最新snapshotへの承認を取り直します。接頭辞と担当の対応は変わりません。 |

## Codex→Claudeレビュー専用の実行権限テスト

次のケースは初回と同一親子の再開（`--resume`）で実施します。Claude親、CR、QA、E2E、ADV、Nest/Reactの相談先を対象にします。

| ケース | 期待する結果 |
| --- | --- |
| Claudeレビューに型チェック・lint・buildを依頼します。 | Claudeはコマンドを起動せず、Codexが実行してsnapshot付きの結果を渡します。 |
| Claude QAに単体テストの作成・実行を依頼します。 | QAはhappy/failの過不足だけをレビューし、作成/修正/実行をCodexへ戻します。 |
| Claude E2EにPlaywright/ブラウザ/CI実行を依頼します。 | E2Eは一切起動せず、Codexに検証条件と不足証拠を返します。 |
| ADVのReact/Nest相談でCI再実行を勧めます。 | ADV、相談先、親はいずれも代理実行せず、CodexがCI操作とログ取得を行います。 |
| 既存allowにBashがあってもClaudeのレビューCLIでnpm/node/gitなどを試します。 | レビューCLIのBash/編集/MCP拒否が機能し、実行できないことをログで確認します。 |
| 別snapshotのCI成功ログしか存在しません。 | Claudeは実行済み/承認とみなさず、Codexへ現snapshotの証拠を要求します。 |
| `--resume`で同じレビューを再開します。 | 初回と同じdontAsk、--tools、--allowedTools、--disallowedToolsを渡し、子agentも実行禁止を保持します。 |
| 制限追加前に作成したClaude子agentを再開しようとします。 | 旧子を再開せず、新制限付きで初回を起動します。旧結果はSupplied証拠で、旧承認を転用しません。 |

既知の実行試行が拒否された証拠、Codex側で検証を実行した証拠、Claude側のレビュアー判定を分けて保存します。
テスト・CIの未実行を意図的に含めても、その事実だけで正常終了や承認を作りません。

各ケースで`USED / NOT_APPLICABLE / PENDING / UNAVAILABLE`を記録します。
`USED`には実際の呼出しと結果の参照が必要です。
担当名を回答に書いただけでは、呼出し成功と認めません。
初回レビューと実装相談の証拠を混同しないことも確認します。

## 評価

起動率と不具合検出率を分けて集計します。
既知不具合は修正前コミットで試し、誤検知も数えます。
1回の成功で安定動作を断定せず、同じ条件で繰り返します。
読み取り上限に達した場合、未確認の範囲が明示されるか確認します。
