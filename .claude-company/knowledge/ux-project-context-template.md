# Project UX context template

共通UX基準と、プロジェクト固有の条件を対応させる記録用です。
運用は[UX QA guide](ux-qa-guide.md)の`Project context and adaptations`に従います。
このテンプレート自体は、対象プロジェクトの確定要件ではありません。
既存の設計書で管理できる項目は、参照を置き、本文を複製しません。
不明な欄は未確認のまま残し、利用者像や合意を作りません。

## Scope and baseline

| 項目 | 記録 |
| --- | --- |
| プロジェクト・対象機能 | 未確認です。 |
| 対象の作業と利用者層 | 未確認です。 |
| この文書の正本・版・管理担当 | 未確認です。差分案なら、その旨を明記します。 |
| 共通UXガイド | 実際のパスと、コミットまたはファイルハッシュを記録します。 |
| 採用する設計規則 | デザインシステム、アクセシビリティ等の要件と適用範囲です。 |
| 対象端末・入力方法 | 端末、ブラウザー、拡大表示、支援技術などです。未確認を含みます。 |
| 確認日・見直し条件 | 対象者、作業、要件、参照基準の変更を記録します。 |

この文書は、実行許可や安全条件の確認を代替しません。
認証情報や実在者の個人情報は記載しません。

## Target users

| user_group_id | 対象者・利用目的 | PC・Web操作 | 業務知識 | この画面の利用経験 | 依頼者の回答元・確認日 |
| --- | --- | --- | --- | --- | --- |
| GROUP-001 | 未確認です。 | 未確認です。 | 未確認です。 | 未確認です。 | 未確認です。 |

操作スキルは、依頼者への質問で確認します。
依頼文の明記や、同じ対象の確認済み回答は再利用できます。
設計書の利用者像だけで、スキルを確認済みにはしません。
利用頻度や支援技術は、必要な範囲で別項目として記録します。

## Task expectations

| task_id | 利用者の目的・開始条件 | 成功条件 | 必要な測定項目・単位 | 根拠・状態 |
| --- | --- | --- | --- | --- |
| TASK-001 | 未確認です。 | 未確認です。 | 必要性から決めます。根拠のない目標値は置きません。 | UNCONFIRMEDです。 |

人の実測値や感想は、HTMLの空欄に書いても保存されません。
記録者が内容を依頼者へ渡し、依頼者が新しい`ux:`依頼の入力として渡します。
渡す内容は、[UX QA follow-up contract](ux-qa-followup.md)に従います。
AIの操作時間や成功率を、人の測定値に置き換えません。

## Adaptation decisions

差分がある項目だけ、次の記録を追加します。
共通基準のまま使う項目は、適用する基準IDをまとめて記録できます。
各項目の状態は`CONFIRMED / PROPOSED / UNCONFIRMED`です。
`CONFIRMED`には、現行の明示要件か依頼者の確認済み回答が必要です。
AIの案や未回答は、確認済みの根拠を上書きしません。

### UXD-001

| 項目 | 記録 |
| --- | --- |
| 状態 | UNCONFIRMEDです。 |
| 基準ID・共通ガイドの版 | 未確認です。 |
| 適用範囲 | 対象のtask_id、利用者層、画面、状態を記録します。 |
| 共通基準との違い | どの条件を具体化または変更するかを記録します。 |
| 適用する期待 | 観察によって確かめられる結果を記録します。 |
| 理由・利用者への影響 | 根拠と仮説を分けて記録します。 |
| 根拠の種別・参照 | 明示要件／依頼者回答／AIの提案を区別し、source_idを示します。 |
| 確認者・確認日 | 回答者または要件を確認した担当と、実際の確認日を記録します。 |
| 見直し条件 | 対象者や要件、基準の版が変わった場合の影響を記録します。 |
| 関連する確認ケース | HTMLのcase_id、step_id、未確認の検証を記録します。 |

既存画面と同じ、という理由だけでは例外を確定しません。
採用する差分は、明示された範囲だけに適用します。
共通ガイドが更新された場合も、影響のない回答を聞き直しません。

## Questions and pending decisions

| question_id | 対象の差分・不足や食い違い | 依頼者への質問・選択肢と影響 | 回答・出典・日付 | 未決の間の扱い |
| --- | --- | --- | --- | --- |
| Q-001 | 未確認です。 | 判断に必要な点だけ質問します。 | 未回答です。 | 依存する判定と、進められる確認を分けます。 |

未回答を同意とせず、同じ質問を繰り返しません。
必須のAI判断に影響する未決事項は、確認範囲をPARTIALにします。
更新時は変更した差分IDと根拠を残し、過去の判断を追えるようにします。

## Handoff

UX担当は、指定レポートフォルダーへ差分案を新規出力できます。
名前は`project-ux-context-proposal.md`です。既存ファイルは上書きしません。
正本の保存先と更新担当を示し、不明なら未確認のまま引き継ぎます。
権限のある呼出元が、確定した内容を通常の文書変更手順で反映します。
UX担当自身は、対象リポジトリやこの共有テンプレートを編集しません。
